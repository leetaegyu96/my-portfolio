# 포트폴리오 1·3·4 가독성 리디자인

## 목표

1·3·4번 시안의 고유한 시각적 성격은 유지하면서, 2번의 여백과 가독성 및 5번의 구조적인 정보 표현을 적용한다. 방문자가 30초 안에 개발자의 정체성, 대표 경험, 주요 기술을 파악할 수 있어야 한다.

## 공통 편집 원칙

- 한글 본문은 Pretendard를 기본으로 사용하고, 장식용 글꼴은 큰 제목에만 제한한다.
- 본문 크기는 데스크톱 16px 이상, 줄높이는 1.65~1.75로 유지한다.
- 콘텐츠 폭은 약 1,100px, 긴 본문은 65자 안팎으로 제한한다.
- 간격은 8px 계열 토큰으로 통일한다. 관련 요소는 가깝게, 다른 섹션은 충분히 멀리 둔다.
- 색상은 무채색을 중심으로 각 시안의 포인트 컬러 하나만 사용한다.
- 영문 보조 라벨, 번호, 칩, 구분선은 정보 탐색에 도움이 되는 경우에만 남긴다.
- 같은 기술과 설명을 프로젝트, 역량, 기술 스택에서 반복하지 않는다.

## 공통 정보 구조

1. Hero: 직무와 핵심 메시지, 짧은 소개, 연락 링크
2. Summary: 경력과 업무 범위를 보여주는 핵심 수치 4개
3. Selected Work: 대표 프로젝트 3개를 문제·역할·결과 중심으로 표현
4. More Work: 나머지 프로젝트와 사내 제품을 압축된 목록으로 표현
5. Experience: 역할 확장을 하나의 간결한 타임라인으로 표현
6. Capabilities: 역량과 기술 스택을 하나의 섹션으로 통합
7. AI & Workflow: AI 활용을 주장 대신 실제 수행 항목으로 요약
8. Contact: 핵심 문장과 연락처만 유지

## 시안별 성격

### 1번 — Refined Editorial

- 아이보리 배경과 코랄 포인트, 세리프 대제목을 유지한다.
- 세리프는 영문 또는 짧은 대제목에만 사용하고 한글 본문에는 사용하지 않는다.
- 거대한 이름과 잡지식 장식을 줄이고 넉넉한 여백과 얇은 구분선으로 편집감을 만든다.

### 3번 — Clear Bold Type

- 굵고 큰 산세리프 제목과 강한 대비를 유지한다.
- 초대형 문구는 Hero 한 곳에만 사용한다.
- 빨강 또는 기존 포인트 컬러는 핵심 수치와 결과에만 적용한다.
- 모든 섹션이 소리치는 느낌을 막기 위해 본문과 보조 정보는 중립적인 크기와 굵기로 낮춘다.

### 4번 — Calm Warm Paper

- 따뜻한 종이색 배경과 차분한 인상을 유지한다.
- 카드와 목록 수를 줄이고, 넓은 여백과 부드러운 경계로 편안한 읽기 흐름을 만든다.
- 손글씨나 장식적 표현 대신 정확한 정렬과 간격으로 따뜻함을 표현한다.

## 콘텐츠 축약 규칙

- 소개 문단은 2개 이하, 각 문단은 3문장 이하로 제한한다.
- 대표 프로젝트는 3개만 상세히 보여주고, 프로젝트당 핵심 성과는 최대 3개로 제한한다.
- 나머지 프로젝트는 이름, 분야, 핵심 역할 한 줄만 표시한다.
- 사내 제품은 별도 대형 섹션 대신 More Work에 포함한다.
- 기술은 분야별 대표 항목만 표시하고 프로젝트 카드 안에서 다시 나열하지 않는다.
- 반복되는 “개발부터 운영까지”, “오늘의 기능보다 내일의 운영” 문장은 Hero 또는 Closing 중 한 번만 사용한다.

## 반응형 및 접근성

- 760px 이하에서는 모든 다단 그리드를 한 열로 전환한다.
- 모바일 좌우 여백은 최소 20px을 유지한다.
- 본문 대비는 WCAG AA 수준을 목표로 한다.
- 모션은 필수 정보 전달에 사용하지 않으며 `prefers-reduced-motion`을 존중한다.
- 링크와 포커스 상태를 색상 외의 방법으로도 구분한다.

## 검증 기준

- 각 시안에서 동일 문구나 동일 기술이 불필요하게 반복되지 않는다.
- 대표 프로젝트 3개가 첫 주요 스크롤 구간에서 명확히 구분된다.
- 데스크톱과 모바일에서 가로 스크롤이 발생하지 않는다.
- JavaScript가 비활성화돼도 모든 콘텐츠가 보인다.
- HTML 문법 검사 및 주요 링크 검사를 통과한다.
- 1·3·4번 사이의 분위기 차이는 유지되지만 정보 순서와 읽는 방법은 일관된다.

## 범위 제외

- 2번과 5번의 직접 수정
- 새로운 프로젝트 내용이나 정량 성과의 임의 생성
- 프레임워크 도입, 빌드 시스템 추가, 외부 CMS 연동
